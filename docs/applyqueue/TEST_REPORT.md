## 4. Real local Ollama (honest numbers)

- Box: 8 vCPU, **no GPU**. Ollama with `qwen3-vl:2b`. Real browser_use Agent on the Greenhouse-style mock ATS.
- Before 8496f74, every step died at 75 s: `llm_call_timeout` is not a browser_use setting and was silently ignored. Now Ollama gets `llm_timeout=900`, `step_timeout=1200`.
- Result: **5 agent steps in 50 min (3005 s wall), STATUS failed, no submission** (`SUBS []`, outcome "Application was not submitted"). It hit 5 empty `ModelProviderError` responses. Generation ran at about 1–3 tok/s while sharing the CPU with the test suite and a PyInstaller build.
- Conclusion: a 2B vision model on CPU is **not practical** for applying. It failed safely: no false success, no submit. Local models need a GPU / Apple-silicon unified memory, or should only be used for extraction. See `LOCAL_MODELS.md`.

## 6. Known limitations

- Cross-origin iframes in ATS pages are not scanned by the form guard (typing personal data into them is refused unless the iframe's origin is allowed).
- `evaluate`/`send_keys` paths could still trigger a submit that the guard does not see.
- Agent e2e uses a scripted LLM stand-in. Real-model quality is measured only by the Ollama run above.
- The default suite syncs with a local bare git repo; the github.com run is opt-in (env vars) and does not run in CI, because CI never gets a real token. Repo visibility is checked only before a push (pulls from a public repo are harmless, and creds are only written on push).
- The "no access" case was tested with the owner's token against a repo it cannot see (GitHub answers 404 for both). A second GitHub account with read-only access was not available, so the read-only path ("cannot push") is covered only by the mock test.
- macOS: no WebDriver for WKWebView, so the real webview is not driven there, only launched and health-checked.
- Personal data may be typed only on the job's own origins. An employer whose application lives on an ATS domain ApplyQueue does not know (not the job's domain, not in the built-in ATS list) needs that domain added (`apply_domains` on the job, or `APPLYQUEUE_APPLY_DOMAINS`); otherwise the run is refused and goes to a person. There is no Settings UI for this yet.
- A hostile page on the **same** origin as the application (for example an injected "verify your identity" step on the real ATS) is not distinguished from the real form; the URL guard and the form guards still apply there.
- A job with no URL gets a permissive origin policy (any http(s) page).
- Sync: `renew_named` can re-create a lock that another device took over and then released (narrow window; not fixed in M8).
- An EEO select with no "decline" option and no profile data gets no answer, so the run goes to a person.
- A one-word (mononym) name fills Last name with the full name.
- "Not answered" migration (fixed above): profiles saved before this change carry no record of which values were typed. A field missing from the file becomes "not answered", and a value that differs from the old preset is kept as the user's answer. A value **equal** to the old preset (for example sponsorship No) cannot be told apart from an untouched default, so it is **kept**, marked "Please confirm" on the Profile page, and **not used in applications until the user confirms or changes it** (a form that asks it goes to a person). Exceptions: a profile with nothing the user typed (no name, email, résumé fields and so on) has its presets cleared, and years of experience 0 is always "not answered" (as since M9). One click ("These are my answers") confirms all kept values.
- The new "not answered" strings are English in the 12 non-English locales until they are translated.
- When the model API key is rejected, the run stops and the jobs stay pending, but a schedule is not paused: the next scheduled run tries once more (one browser launch) and stops again.
- Wrong-typed profile/settings fields that cannot be repaired (for example an address saved as plain text) are replaced by the default when loaded; the file keeps the original until the next save.
- A page whose HTML keeps streaming is stopped after 35 s; a real ATS that streams its first HTML for longer than that would be cut off (`APPLYQUEUE_PAGE_LOAD_BUDGET_S` raises it).
